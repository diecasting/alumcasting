## 12. Staged Release Plan

### Stage 1 — Validated Content Pages

Scope:

- Reviewed English page-level content changes from Batches 1–9.
- Exclude `content/_index.md`.
- Exclude `content/ko/**`.
- Exclude shared template, robots, Alias, deploy-workflow and tracking changes.

Dependencies and approvals:

- SEO owner approval of release manifest.
- Business/legal approval for any page containing a company-specific factual
  claim.
- Build from an isolated release branch or commit; do not deploy the mixed
  worktree directly.

Pre-deployment tests:

- Production build and full structural validation.
- Fact-risk scan.
- Canonical/robots/Sitemap snapshot.
- Content-only diff review.

Rollback:

- Revert the approved release commit through the normal Git workflow.
- Preserve a previous production artifact or commit reference.

Post-deployment:

- Verify representative pages, Sitemap, Canonical and form.
- Confirm no unexpected 404 or noindex.

Success criteria:

- Approved pages match the reviewed source.
- No protected configuration changed.
- No new technical or factual regression.

### Stage 2 — Approved Page-Level Technical Fixes

Scope:

- Explicitly listed page or configuration fixes not suitable for Stage 1.

Dependencies:

- Technical approval and a staged URL/config manifest.

Tests:

- Production/Staging build.
- Canonical, noindex, Sitemap, internal-link and form verification.

Rollback:

- Disable/revert the specific change.

Success criteria:

- Intended output changes and no unrelated URL behavior.

### Stage 3 — URLs, Aliases, Canonical, Robots and Sitemap

Scope:

- Approved 301 policy for selected aliases.
- Korean route disposition.
- robots.txt deployment with production Sitemap.
- Sitemap/indexability changes.

Dependencies:

- Hosting 301 capability.
- Business approval for Korean routes.
- Final URL mapping and rollback table.

Tests:

- 301 chains and final canonical.
- Sitemap inclusion/exclusion.
- Robots direct fetch.
- Google URL Inspection after deployment.

Rollback:

- Restore prior redirect/config version.
- Preserve Alias files until verification is complete.

Success criteria:

- One-hop redirects, no loops, no unintended noindex, Sitemap reachable.

### Stage 4 — RFQ Tracking

Scope:

- Approved RFQ tracking package only.

Dependencies:

- Privacy/consent approval.
- GA4/Formspree/CRM validation access.
- Feature flag default off before release.

Tests:

- CTA, form start, submit attempt, confirmed success, fallback.
- Event deduplication.
- No PII in analytics.
- Reconciliation with test submission.

Rollback:

- Set tracking feature flag off.
- Preserve native form behavior.

Success criteria:

- Events validated and matched to test receipts.

### Stage 5 — Shared Templates and Homepage

Scope:

- Approved Homepage claim remediation.
- Approved shared UI/schema changes.

Dependencies:

- Business evidence, legal approval and full regression review.

Tests:

- Full Production/Staging build.
- All canonical, schema, form and claim checks.

Rollback:

- Restore prior shared-template release if any critical regression is found.

Success criteria:

- Claims match evidence and all sitewide checks pass.

### Stage 6 — Post-Release Monitoring

Monitor:

- HTTP status and redirect chains.
- Canonical and indexing.
- Sitemap discovery.
- GSC clicks/impressions/query movement.
- Form submissions and data quality.

Do not claim success from short-term movement. Use comparable 28-day windows and
allow for recrawling.
